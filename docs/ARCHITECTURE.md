# 架构与迁移现状

此文档描述尚未发布的重构分支；发布前仍需完成 WebDAV 映射、外链导入安全验证、跨进程编辑并发保护和完整回归。

管理 API 使用 `/api/folders`、`/api/files`、`/api/shares`；公开 API 使用 `/api/public/shares`。SQLite 中的 Folder 表通过 parent_id 表示目录树，FileItem 的 folder_id 为空时属于根目录。文件内容保存在 `storage` 下，以原有 stored_name 平铺存放，目录移动不移动磁盘文件。旧 Group、FileShare 及兼容路由暂时保留，以保持旧分享 token 可用。

公开目录分享对每次请求检查目录是否位于分享目录子树内。旧系统分组 token 仅能访问原系统分组中仍位于根目录的文件，不暴露其他根目录项。分享密码经过 PBKDF2 哈希，密码授权 cookie 有有效期；修改密码、撤销分享或分享过期会立即阻止新请求。

数据库使用 schema_version 表。首次迁移旧库前通过 SQLite backup API 创建 `cryovault.db.pre-v0.3.0-*.bak`。迁移保留 stored_name、旧 token 和 WebDAV 同步状态，并对目录内重复名称编号。同步引擎在新版映射可用之前拒绝运行，避免误删远端数据。

升级前应独立备份整个数据目录，并先在副本上验证。回滚时停止服务，将升级后的数据库及整个存储目录另行备份，再恢复迁移前数据库备份和 v0.2.2 程序。升级后新增或修改的文件和元数据无法由迁移前数据库恢复，需要从升级后的完整备份单独处理；不要覆盖这些文件。

管理员会话为进程内随机会话，重启会使其失效，当前仅支持单进程部署。空管理员令牌允许无认证管理请求并在启动时输出警告；公网部署必须设置强令牌和 HTTPS。文件未加密。默认关闭 API 文档。

在线编辑使用文件内容 etag 和进程内锁；多进程及进程崩溃时的文件与数据库一致性尚未得到保证。链接导入的 DNS 校验与连接使用的解析可能不同，尚需防范 DNS 重绑定。不要在不可信管理环境下使用外链导入。
